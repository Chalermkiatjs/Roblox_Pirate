# PirateOcean

Roblox MVP for an ocean-based pirate survival game where the ship is the character.

Core loop:

1. Port
2. Prepare ship
3. Sail
4. Islands and ocean events
5. Loot
6. Choose to go deeper or return
7. Sell, collect, craft
8. Upgrade ship

## MVP Scope

- 1 starter port
- 5 islands
- 3 ship tiers
- 1 Kraken boss encounter
- 5 random ocean events
- Treasure rarity and collection systems
- Basic crew support
- Ship upgrade progression
- Save data architecture
- PvE-first gameplay

## Tooling

This project is structured for Rojo.

Recommended setup:

1. Install Rojo, or install Aftman and run `aftman install` from this folder.
2. Open Roblox Studio.
3. Open the Rojo plugin.
4. Run `rojo serve default.project.json` from this folder.
5. Connect the plugin to the running Rojo server.

The game source maps into `ReplicatedStorage`, `ServerScriptService`, and `StarterPlayerScripts`.

## Project Layout

- `src/shared`: shared config, schemas, constants, and utility modules
- `src/server`: authoritative gameplay systems and services
- `src/client`: player-facing client controllers
- `docs`: architecture notes, data schema, and roadmap

## Current MVP Behavior

The server creates a simple runtime loop:

- players receive a ship profile from saved data or defaults
- port preparation and upgrades are modeled through `ShipService`
- ocean events are selected by depth and risk through `OceanEventService`
- island loot and boss rewards are generated with rarity-aware treasure tables
- collection state, crew assignments, cargo, gold, and ship upgrades are saved through `DataService`

## Playable Prototype

Press Play in Studio after connecting Rojo. The port, five islands, three ship models, ocean and Kraken are generated by the server at runtime (the edit viewport stays empty).

- Select Set Sail to board your own ship. Use the standard VehicleSeat controls (W/S forward/reverse, A/D steering, or mobile/gamepad controls).
- Sail toward the island signs. Select Collect within 82 studs of an island. Each island refreshes its treasure after 25 seconds.
- Cargo is limited by ship capacity. The collection catalog remains after selling or sinking.
- Sail back within 150 studs along the harbor coastline, then Sell, Upgrade or Dock. The Sloop costs 650 gold; the Brigantine costs 2400.
- Recruit Lina, Bo or Mara at the port counters with proximity prompts. Crew bonuses affect speed, cannon power or cargo space.
- Ocean events occur every 40 seconds away from port while seated. Deeper water requires a higher ship tier.
- Sail the Brigantine near the Kraken and select Fire. Ship defeat returns the boat to port and clears cargo.

Studio sessions use temporary profiles and reset progress on Stop. Published servers use DataStore. A failed load is never saved over existing data. Session locking, retry policy and autosave are still required before a public release.

Portable Rojo is installed at `D:\Personal Project\Tools\Rojo\7.4.4\rojo.exe`:

```powershell
cd "D:\Personal Project\PirateOcean"
& "D:\Personal Project\Tools\Rojo\7.4.4\rojo.exe" serve default.project.json
```

This is a blockout prototype with anchored, server-driven boats and a turn-based Kraken encounter. Art, physical sailing, player crew sharing and crafting remain on the roadmap.

## Verification

Run `D:\Personal Project\Tools\Luau\0.741\luau.exe tests/config.spec.luau` from this project to check island access, progression, rarity tables and Kraken balance.

During Studio Play, use the server Command Bar to run the optional temporary-data service smoke test:

```lua
require(game.ServerScriptService.PirateOceanServer.Tests.ServiceSmoke)()
```

The service smoke test checks cargo capacity, selling without clearing collection, upgrades, crew bonus and the boss reward. It does not modify a real player profile.

Manual Studio checks: Set Sail; steer forward and reverse; collect at Starter Cove; sell at harbor; upgrade after earning gold; enter deeper seas; fire near Kraken; sink and confirm cargo loss; Stop and confirm the runtime world disappears. Test mobile/gamepad controls and two-player sessions before publishing.
