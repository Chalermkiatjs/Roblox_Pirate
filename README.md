# PirateOcean

Roblox MVP for an ocean-based pirate survival game where the ship is the character.

Core loop:

1. Port
2. Prepare ship
3. Sail
4. Islands and ocean events
5. Loot
6. Choose to go deeper or return
7. Sell, collect, craft
8. Upgrade ship

## MVP Scope

- 1 starter port
- 5 islands
- 3 ship tiers
- 1 Kraken boss encounter
- 5 random ocean events
- Treasure rarity and collection systems
- Basic crew support
- Ship upgrade progression
- Save data architecture
- PvE-first gameplay

## Tooling

This project is structured for Rojo.

Recommended setup:

1. Install Rojo, or install Aftman and run `aftman install` from this folder.
2. Open Roblox Studio.
3. Open the Rojo plugin.
4. Run `rojo serve default.project.json` from this folder.
5. Connect the plugin to the running Rojo server.

The game source maps into `ReplicatedStorage`, `ServerScriptService`, and `StarterPlayerScripts`.

## Project Layout

- `src/shared`: shared config, schemas, constants, and utility modules
- `src/server`: authoritative gameplay systems and services
- `src/client`: player-facing client controllers
- `docs`: architecture notes, data schema, and roadmap

## Current MVP Behavior

The server creates a simple runtime loop:

- players receive a ship profile from saved data or defaults
- port preparation and upgrades are modeled through `ShipService`
- ocean events are selected by depth and risk through `OceanEventService`
- island loot and boss rewards are generated with rarity-aware treasure tables
- collection state, crew assignments, cargo, gold, and ship upgrades are saved through `DataService`

## Playable Prototype

Cutlass combat, separate PLAYER/HULL health, stamina and persistent bounty are
now available. Equip Cutlass from the backpack; left click slashes, T thrusts,
R uses a heavy attack, F/right mouse guards, and Q feints during windup. Use the
Spar prompt at the harbor's Sparring Mate to practice. Island raiders grant
bounty; the training opponent does not. See `docs/combat.md` for rules, gamepad/
mobile controls and Studio verification.

Press Play in Studio after connecting Rojo. The port, five islands, three ship models, ocean and Kraken are generated by the server at runtime (the edit viewport stays empty).

- Select Set Sail to board your own ship. A/D steer; tap W to increase the speed stage or S to decrease it. Holding a key does not repeat stage changes.
- Voyages start stopped. Speed stages are Reverse, Stopped, Paddles, Sail I (half sail) and Sail II (full sail). Tap W three times from stopped to reach full sails; tap S three times to stop and once more to reverse. The stage bar displays the selected level. The server checks that each step comes from your own helm.
- During a voyage, leave the helm and approach the bow capstan. Press E to drop anchor instantly, or press E while anchored to begin raising it. Walk around the capstan for two full turns in either direction; the handles rotate and display progress. Leaving the station pauses hauling, and reversing direction unwinds progress. Movement is checked on the server.
- The selected stage persists after releasing W/S. Paddles and reverse use 28% of tier speed; sails cruise according to deployment and wind. Mobile uses the + and - touch controls; gamepad uses D-pad up/down or R2/L2 for speed steps and the left stick for steering.
- Sail deployment takes 1.4 seconds from furled to full; partial transitions take proportionally less time. Sail size changes visibly and the HUD shows deployment percentage and measured speed.
- Wind is a simplified fixed breeze toward negative Z. Sailing into it is slower but remains possible. Leaving the helm stops propulsion and stows the sail.
- Sail toward the island signs. Select Collect within 82 studs of an island. Each island refreshes its treasure after 25 seconds.
- Cargo is limited by ship capacity. The collection catalog remains after selling or sinking.
- Sail back within 150 studs along the harbor coastline, then Sell, Upgrade or Dock. The Sloop costs 650 gold; the Brigantine costs 2400.
- Recruit Lina, Bo or Mara at the port counters with proximity prompts. Crew bonuses affect speed, cannon power or cargo space.
- Ocean events occur every 40 seconds away from port while seated. All ship tiers can sail across depth zones; island rewards and ocean events still require a suitable ship tier.
- Sail the Brigantine near the Kraken and select Fire. Ship defeat returns the boat to port and clears cargo.

Studio sessions use temporary profiles and reset progress on Stop. Published servers use DataStore. A failed load is never saved over existing data. Session locking, retry policy and autosave are still required before a public release.

The ocean is native Terrain water with a 32-stud depth. Swimming uses the standard Roblox character controller. Jump off your boat to swim; approach its helm and use Board to rejoin it during a voyage. Truss ladders provide exits at the dock and each island.

Ships use welded, unanchored assemblies and native water buoyancy. Hull mass is redistributed into low, slightly aft ballast without changing total ship weight. Propulsion acts along the measured heading; speed-dependent rudder force acts at the stern, keel drag acts forward of the center of mass, and water resistance damps yaw. Rudder input eases in, long hulls respond more slowly, and reverse travel reverses steering. AlignOrientation maintains pitch/roll using primary-axis alignment without commanding yaw. Docked ships are anchored. Server-owned physics keeps movement authoritative. Normal sailing never teleports the ship; docking, sinking and out-of-bounds recovery reset its position and velocity.

Walking and combat now use a third-person shoulder camera; the helm uses a ship-sized chase camera above the stern. Move the mouse to look directly in either mode: cursor is hidden and locked to the center, with no right-button drag required. Hold Alt to release the cursor for HUD buttons. Roblox menus, text entry, the treasure ledger and lost window focus also release it. Right mouse remains available for guarding with the cutlass. Scroll to zoom, drag on the right side of a touch screen, or use the right gamepad stick. The character faces mouse-look direction while on foot; swimming and climbing keep native character rotation. Seated players hand off to the ship or native seated camera. Ship view recenters after idle touch/gamepad look, but keeps the mouse-selected angle. Both cameras adjust for portrait framing and check scenery collision. Tune `src/shared/ShipCameraConfig.lua` and `src/shared/CharacterCameraConfig.lua`; `tests/ship_camera.spec.luau` checks ship framing and follow math. Studio playtesting is still required for camera collision, input, Alt/menu behavior and transitions.

Terrain waves are visual; this is not a fluid or wave-displacement simulation. Native buoyancy uses the water surface. The orientation constraint responds to sampled water height and vertical wave velocity at the bow, stern and sides, so the hull lags behind wave impacts instead of snapping directly to the wave slope. Hull density, thrust, steering and water settings live in `src/shared/WorldConfig.lua`; swell/rocking/impact settings are in `src/shared/OceanConfig.lua`, and stage settings are in `src/shared/SailingConfig.lua`.

Ocean presentation uses darker water, increased reflectance, moving native waves, afternoon light, atmosphere and clouds. Client-only bow/side splashes and foam respond to motion and estimated wave impacts, alongside stern wakes and paddling oars. Water raycasts suppress impacts on land, and tilted attachment positioning keeps spray at the waterline. Effects use Roblox's bundled particle texture, are distance-limited and require no extra plugin. Water surface detail depends on graphics quality. Native wave size is set to its 1-stud maximum; the swell sampler is approximate, not an exact Terrain shader simulation.

This is a blockout prototype with a turn-based Kraken encounter. Art, player crew sharing and crafting remain on the roadmap.

## Verification

### Reference Frigate

The revised Blender ship has a Roblox FBX at
`assets/roblox/reference_frigate_roblox.fbx`. Import it into Workspace as
`ReferenceFrigate`, keep mesh merging off and vertex colors enabled, then
Stop/Play after syncing the latest Rojo code. The server automatically adds the
helm, collision proxies, buoyancy and animated sails/rudder. It preserves all
tier stats and falls back to the blockout boats when the asset is missing.
See `assets/roblox/README.md` for the import settings and Studio smoke test.
The user confirmed import into Studio; asset IDs are not recorded in this repo.
Hands-on verification of the latest corrections is still pending. The runtime
art scale is now 3x, with matching colliders, bow/stern-based orientation, a helm
behind the wheel, complete aft floors, and a stock-centered rudder hinge.
The revision-2 FBX closes the plank gaps, corrects the wheel's mounting/grip side,
and adds a gun-deck interior with an open hatch, stairs, beams, cargo and berths.
Reimport this updated FBX, then sync code and Stop/Play. Old imports retain a
closed main floor and their old helm position until the revised art is present.

Run `tests/frigate.spec.luau` with the portable Luau interpreter to check moving
component classification, top-fixed sail scaling and rudder limits.
The same test also covers scale, import heading, helm placement and aft-floor
coverage, hatch openings, interior headroom, step heights and legacy compatibility.
The Blender `validate_interior.py` checks actual plank seams and floor/hatch
geometry with ray casts. Run `tests/waves.spec.luau` to check swell bounds, responsive rocking lag, safe pitch/roll limits,
impact strength and water-plane positioning while tilted.

Run `D:\Personal Project\Tools\Luau\0.741\luau.exe tests/config.spec.luau` from this project to check island access, progression, rarity tables and Kraken balance.

Run the same tool with `tests/motion.spec.luau` to check acceleration, braking, reversal and frame-rate stability. These mathematical checks do not simulate Roblox buoyancy or character swimming.

Run `tests/sailing.spec.luau` to check valid stage values, increasing speed, braking, upwind return travel and stage transitions at several frame rates.
